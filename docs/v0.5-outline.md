# SPEC v0.5 — Outline (not the document)

Status: outline for discussion. Nothing here is normative, and nothing here is
decided. v0.4's outline was locked at v2.4 before the spec was written; this one
is at v0.1 and is explicitly a starting position.

**What changed since v0.4 shipped:** Prompt 07 landed the overlay level, four
two-key review passes accumulated a queue of recorded deviations and deferred
definitions, the retarget pass over prompts 08–15 found two contracts those
prompts cite that no spec version has ever contained, and three research
syntheses landed in `docs/` — `industry-gap-analysis-and-z-axis.md`,
`move-parity-and-virtual-set-roadmap.md`, `news-broadcast-features-research.md`.
All three are marked non-normative until adopted. This outline is where that
adoption gets argued.

---

## 0. What v0.5 is for

v0.4 was a patch-class revision: wire additions, normative sentences, one hook
removed. v0.5 has a different shape, because the queue in front of it splits
three ways:

1. **Things already built that no sentence makes law.** Cheapest and most urgent
   — an implemented behaviour with no normative statement is a behaviour the next
   agent may "fix".
2. **Recorded deviations** where implementation and spec already disagree in
   writing, awaiting ratification or reversal.
3. **Research-derived capability gaps**, which are the largest and the least
   urgent, and which must not be adopted as a batch.

The discipline that served v0.4 applies: **confirmed content first, candidates
second, and a candidate is promoted by evidence rather than by enthusiasm.**

## 2. Already built — needs only the sentence that makes it law

The highest-value, lowest-risk category. Each of these is implemented, tested,
and falsified on `main` today, and none of them is normative.

| Item | Implemented | Research concurrence |
|---|---|---|
| **Fallback composites above the overlay level.** A fallback cut covers ticker, bug, banner and clock; recovery restores the pre-fallback on-air set; alpha stays a pure function of the master clock | `render.rs` — `show_fallback` gates the whole scene+overlay branch. Falsified: `if false` → `fallback_covers_overlays` fails | **Gap analysis §3.4 states it in the same words** — "The fallback slate composites above the overlay level. A fallback cut MUST cover tickers, bugs, and banners." This is now a text-derived rule, not a prompt-derived one |
| **Overlays persist across a take, and a take never re-keys an animation in flight** | `overlay_persists_across_take`, `animation_immune_to_take` | Gap analysis maps DSK as "Present, structurally exact" |
| **Empty `visibleOverlays` clears the on-air set wholesale** | v0.4 §5.9.4 already normative; implementation matches | — |
| **Idempotent overlay no-ops forward no directive** | `commands/state.ts`; `stateVersion` bumps once, `data.noop: true` | Gap analysis's air-status concurrency point is adjacent but separate |

**Recommendation:** adopt this block as v0.5's confirmed core. It is four
sentences and one table row, it closes the gap between what the engine does and
what the document promises, and it costs no implementation work.

## 3. Research-derived candidates, triaged

Not a batch. Each row is a candidate with its own evidence bar.

### 3a. Strong candidates — cheap, and they close a real operational gap

| Candidate | Source | Why now |
|---|---|---|
| **`view.ftb` command** — fade the entire View (scene + overlays) to black, mirroring hardware FTB | Gap analysis §3.4 | The fallback path already composites above overlays; FTB is the same topology with a ramp. Small, and the absence is conspicuous next to a built fallback |
| **Clean feed** — `outputs.record.source: "program" \| "clean"`, where `clean` composites the scene level only | Gap analysis §3.3 | v0.2 declared an isolation hook and never implemented it. With render-to-texture sub-scenes already in place this is an additional encoder tap, not a re-composite. Archive recording without burned-in bugs is a genuine broadcast requirement |
| **Failover drill as a named acceptance criterion** — kill the render process mid-show; fallback slate MUST appear within N frames; recovery MUST restore prior scene state | Gap analysis §4.5; features research item 5 | The watchdog, degradation ladder and fallback slate all exist. What is missing is the *drill*, and the dress rehearsal harness can already run it. Untested redundancy is not redundancy |
| **`itemStatus` event stream** (ready / armed / live / missing / error) emitted on every rundown-item state transition | Gap analysis §4.2; features research item 1 | This is the MOS status round-trip, which the features research calls the biggest usability gap between a demo and a trusted newsroom tool. NBE has the telemetry bus and monotonic `stateVersion` already; the loop back to whoever authored the item is what is missing |

| Candidate | Source | The argument against doing it now |
|---|---|---|

## 4. The code finding that is not a spec item — but might need a sentence

**The preflight bound is a coin flip on the reference fixture.** On the normative
baseline machine, release `nbe-preflight` on `valid_show_v0.3` ran 33.6 / 39.6 /
42.4 / 54.7 / 67.4 / 81.7 / 106.3 s across seven samples; `preflightBound`
derives 67,500 ms and `runPreflight` enforces it with SIGKILL. Two of seven runs
would be killed, failing `show.load` on a valid package.

This is a defect to fix in code, and it is queued as **recommended before Prompt
08**. It reaches this outline only because of one question: **does the spec want
to say anything about preflight's own cost bound?** §19 defines preflight's exit
status and report schema but says nothing about how long it may take or who
decides. An implementation-defined timeout that can reject a valid package is
arguably a normative gap. Recorded as a question, not a proposal.

## 5. Corrections to the research inputs

The syntheses are input, not authority, and two of their claims do not survive
contact with v0.4.

1. **"NBE's spec is currently silent on captioning entirely"** (`news-broadcast-features-research.md`) is **false against v0.4.** Captions are normative: the glossary row at line 221 and §10.6 at line 1795 both specify a WebVTT-class sidecar alongside the stream, §25.2's resolved decisions fix burn-in as a dedicated Overlay element on the DSK level rather than a post-composite shader pass, and §27 item 4 already carries the open question of WebVTT-to-master-clock sync. The **real** gap is the one `industry-gap-analysis-and-z-axis.md` §4.1 states correctly: CEA-608/708 *embedding* and FCC Part 79 *compliance depth* (accuracy, ±2-frame sync, completeness, title-safe placement) on top of the sidecar that already exists. Adopt the gap analysis's framing; do not adopt the features research's.
2. **The fallback/FTB item is no longer a gap at all.** Gap analysis §3.4 lists "FTB above overlays" as "Unspecified" in NBE. That was true when written; the overlay level has since implemented and falsified it. What remains is the normative sentence (§2 above) and the `view.ftb` command (§3a).

Both corrections point the same way: the research is a year-shaped snapshot of a
moving tree, and every row of it must be re-checked against the tree before it is
promoted. That is the same rule the prompts just failed for four spec revisions.
